# Extras: AcerUltraX (audio), PreySense comparison, Purified Voice (mic/speaker AI noise reduction)
All Windows-side checks below were done on this PH16-71 (Windows 11, Realtek ALC245 + Intel SST). Nothing here was run on Linux.

## 0. Most important finding for the headset mic (read first)
AcerUltraX's README documents exactly your problem: *"PH16-71: the headset microphone on the 3.5 mm jack does not work on Linux kernels from before August 2026."* The cause is a missing kernel quirk; mainline fixed it with commit `04a8e286bb2e` "ALSA: hda/realtek: Add quirk for Acer Predator PH16-71" (adds `SND_PCI_QUIRK(0x1025, 0x166c, "Acer Predator PH16-71", ALC2XX_FIXUP_HEADSET_MIC)`). That is why the earlier attempt did not work on an older kernel. Two fixes:
1. **Update to a kernel that contains that commit**, or
2. **Force the same fixup on your current kernel** (documented workaround from AcerUltraX; this laptop's codec sits behind the Intel SOF driver, hence the SOF module name):
   `echo 'options snd_sof_intel_hda_generic hda_model=alc2xx-fixup-headset-mic' | sudo tee /etc/modprobe.d/acerultrax-headset-mic.conf`, rebuild the initramfs, reboot.
   `fix_headset_mic.sh --known-fix` does that (and also writes the legacy `snd_hda_intel model=` line and rebuilds the initramfs). `--auto` now tries this model name first.

## 1. AcerUltraX (https://github.com/fawaz7/AcerUltraX): Acer's DTS:X Ultra sound on Linux
- It is an **audio** project (runs Acer's DTS engine natively under PipeWire; sound modes Music/Movie/Game 1-3/Voice/Custom/Off, per-device profiles, 10-band EQ). It does **not** touch the microphone and uses no WMI/EC.
- **Model support:** its README lists **PH16-71 as "Verified against Windows"**, so nothing needs reverse-engineering on this model; install it as documented (PipeWire + WirePlumber; `.deb`/`.tar.gz install.sh`/AUR/Nix; first start: "Download and set up" fetches your laptop's DTS files from Acer, about 20 MB; headphone models optional 386 MB). CLI: `acerultrax-cli setup|status|mode <name>`.
- **What this Windows install has (to compare with what it downloads):** DTS:X Ultra app `DTSInc.DTSXUltra 1.14.2.0`; `DTSInc.DTSSoundUnbound 2026.3.0.0`; DTS APO driver `dtsapo4x64.inf` 1.12.4.0 (2023-07-25); `dtsapo4ultraacerextensionpkg.inf` 1.12.4.0; `dtsapo4xultrahsa.inf` 1.11.5.0; Realtek extension `hdx_acerext_xperi4_rtk_gen4.inf` 6.0.9652.1; service `DtsApo4Service`. The Acer support download it falls back to is the "XPERI DTS" audio driver + "XPERI DTS Utility".
- On the Linux side the speaker DTS effect needs SOF audio (`dsp_driver=3`); if you use the legacy driver for the jack (`dsp_driver=1`) the DMIC array is lost, so prefer SOF + the model fixup above.

## 3. Acer Purified Voice Console
**What it is (Windows, v2.0.10.0, package `AcerIncorporated.AcerPurifiedVoiceConsoleR`):** a small UI over Realtek's audio-processing engine (`RtkAudioCore.dll`). Its screen has: *Microphone*: Input Source (dropdown, here "Microphone" = the headset jack mic), **AI noise reduction** on/off, Microphone Mode Notification; *Speaker*: Output Source (Headphones/Speakers), **AI noise reduction** on/off. The package also ships mode icons (Off, Omni, Uni, HQ Podcast Recording, HQ Stereo Recording) that this version's UI does not show: those are microphone-array pickup modes (omni-directional / uni-directional beamforming) for the built-in digital array.
**What the toggle changes (measured):** toggling Microphone AI noise reduction off/on changes only the jack microphone's audio-effect property store under `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\MMDevices\Audio\Capture\{6d874afb-7c47-402b-b9fd-370534618fbb}\FxProperties\{12325c6d-6d93-4ab3-bff6-d04968d361dd}\User\` (properties `{911dff54-0b79-4e96-b3de-577f235b619b},2/15/45/72` and `{70eefb05-aa49-4472-99f6-cbc707f1e576},6`: 1 / 20006 when on, 0 when off). It was set back to On afterwards (`re/analysis/pv_diff.txt`). So the effect is a proprietary Realtek neural-network audio plug-in (APO; model data in the driver package, `netstate2_a_AD98_g.dat` 15 MB, `hdx_acerext_apot_*`), it runs inside the Windows audio engine, and **cannot be run or copied to Linux**. (AcerUltraX shows that a Windows DLL can be loaded on Linux for the DTS speaker engine; I did not attempt that for the Realtek mic engine: it is tied to the Windows audio-engine interfaces and to Realtek's driver.)
**The Linux port (functional equivalent):** `linux_tools/purified_voice.sh` builds the same two things with an open-source neural denoiser on PipeWire: a virtual source **"Purified Voice Mic"** (real mic -> DeepFilterNet or RNNoise -> apps) and a virtual sink **"Purified Voice Speaker"** (apps -> denoiser -> your output). `./purified_voice.sh mic on`, `speaker on`, `strength mic 80`, `status`. Needs `noise-suppression-for-voice` (RNNoise LADSPA) or DeepFilterNet's LADSPA plug-in. For the microphone path to exist at all, the headset-mic fix in section 0 must work first.
**Honest limits:** the Realtek model is not reproduced (different engine, similar goal: removing steady and background noise from the voice); the Omni/Uni pickup modes need the built-in DMIC array via SOF and have no equivalent here; **untested on Linux**.

## 4. Fn keys, mic-mute LED and the Predator key (measured on this laptop, Windows; `re/tools/fn_probe.ps1`, logs `re/analysis/fn_probe2.log`, `fn_probe4.log`)
The keyboard (Chicony `04F2:0117`) exposes these HID interfaces; the probe read every one that Windows lets a normal program open:
`MI_00` keyboard (not openable), `MI_01` vendor page 0xFF00 (65-byte reports, no key traffic seen), `MI_02` with collections `COL01` consumer control (page 0x0C, 5-byte reports), `COL02` mouse (not openable), `COL03` **vendor page 0x88** (3-byte reports), `COL04` wireless radio controls (page 0x01 usage 0x0C), `COL05` (not openable), and `MI_03` the lighting interface (page 0xFF02).

| Key | What arrives | Linux |
|---|---|---|
| **Fn+F1 / F2 / F3** | consumer-control report `02 00 01 00 00` (mute), `02 00 02 00 00` (vol -), `02 00 04 00 00` (vol +), then `02 00 00 00 00` | standard: the kernel makes KEY_MUTE / VOLUMEDOWN / VOLUMEUP, nothing to port |
| **Fn+F4** | not tested on purpose (Sleep) | standard ACPI sleep |
| **Fn+F5 / Fn+F6** | consumer-control report `02 00 00 08 00` / `02 00 00 04 00` (no key reaches Windows apps; handled below the app level) | standard consumer usages: kernel handles them |
| **Fn+F7** | Windows apps see `LWin` followed by another key (a Win-key combination injected by the keyboard) | works as a normal key combo |
| **Fn+F8 (mic mute)** | a normal key **F15** (scan code 0x66) on the keyboard interface | KEY_F15 reaches Linux. Bind it to `linux_tools/mic_mute_toggle.sh`. |
| **Fn+F9 (airplane)** | standard HID Wireless-Radio-Control report `08 01` on `MI_02/COL04` | kernel maps it to KEY_RFKILL by itself; nothing to port |
| **Fn+F10 (touchpad)** | vendor report on `MI_02/COL03` (page 0x88): `04 80 FF`, release `04 00 00` | **needs `linux_tools/acer_fn_keys.py`** (no kernel driver for page 0x88) |
| **Fn+F11 (keyboard light down)** | `04 7D FF`, release `04 00 00` (same interface) | `acer_fn_keys.py` lowers the keyboard brightness over the keyboard protocol |
| **Fn+F12 (keyboard light up)** | `04 7C FF`, release `04 00 00` | `acer_fn_keys.py` raises it |
| **Fn+S** | ScrollLock (scan code 70, twice for press and release) | normal key |
| **PREDATOR key** | vendor report `04 81 FF` on press, `04 00 00` on release (same page-0x88 interface). Hold: the press report arrives once and the release comes when you let go (3 s hold measured as 143.10 s to 147.65 s in the log). Double tap: two press/release pairs 0.2 s apart. | `acer_fn_keys.py --predator-tap CMD --predator-long CMD --predator-double CMD` runs a command of your choice for tap / hold (>=0.8 s) / double tap |
| Fn+Esc, Fn+arrows | no event recorded in my run (probably not pressed during the prompt, not decoded) | unknown; test with `evtest` on Linux |

No Acer WMI events (`APGeEvent`, `AcerGenericEvent`) arrived for any of these keys: they all travel over HID, so no WMI listener is needed.
**Mic-mute LED:** the owner confirmed the F8 light came on when Windows muted the microphone by software and went off when unmuted, so the LED follows the capture endpoint's mute state: it is driven by the audio codec/driver (GPIO), not by the keyboard. On Linux that needs a codec GPIO plus the kernel's micmute LED trigger; mainline has no such quirk for 1025:166c. `linux_tools/micmute_led_probe.sh` finds the GPIO (tries ALC245 GPIO0-5 with `hda-verb` and asks which one lights F8), writes `micmute_gpio.txt`; with that number a two-line fixup (like the existing `ALC245_FIXUP_ACER_MICMUTE_LED`) can be written. **Not done on Windows because a codec GPIO cannot be read from there.**

- **Microphone (headset jack)** (`Capture\{6d874afb-7c47-402b-b9fd-370534618fbb}\...\User`): only the AI noise reduction: on = mode 3, `,2`=1, `,15`=`,45`=20006, `,72`=1, `{70eefb05-aa49-4472-99f6-cbc707f1e576},6`=1; off = all 0.
- **Headphones output** (`Render\{0a3fac1d-95a1-4c03-bca8-c1b9fed50d52}\FxProperties`): AI noise reduction `{70eefb05-aa49-4472-99f6-cbc707f1e576},3` = 1/0 and mode `{16b04f29-...},0` = 3/0.

**Linux port (functional equivalent): `linux_tools/purified_voice.sh`** now mirrors all of those options: `mic on|off`, `mic mode off|personal|conference` (All Off removes the filter; Conference = RNNoise/DeepFilterNet at moderate strength; Personal = stronger gating, closest equivalent of "focus on your voice"), `speaker on|off` (the Output AI noise reduction as a virtual sink in front of your real output), `strength mic|speaker N`, `notify on|off` (the Microphone Mode Notification, via notify-send). Honest limit: the real Personal Call is array beamforming + a neural model; on Linux the digital mic array needs SOF, and true beamforming would need PipeWire's WebRTC echo-cancel module with the array geometry, which I could not measure.
**State left on this laptop:** Conference Call (mode 3) on the array, AI noise reduction On for Microphone, Microphone Array, Headphones and Speakers (original values). The app window was left showing "Microphone Array" as the selected input source (it started on "Microphone"): cosmetic.

## 6. CPU power limits and undervolting
Windows could not read the real PL1/PL2: that needs a kernel driver (PawnIO, ThrottleStop, HWiNFO) and Intel's DTT data file on disk (`ipf_cpu.inf` `dsp.dv`, "Device Support Packages / adl_proc") is a generic template, not the OEM numbers. The CPU is an **Intel Core i7-13700HX (16 cores, 24 threads)**. `linux_tools/cpu_power_undervolt.sh info` prints the real baseline on Linux (RAPL powercap + MSR 0x610), `limits PL1 PL2` sets it, and `uv-check / uv-get / uv-set / uv-reset` use the voltage-offset MSR 0x150 (core and cache planes, 10 mV-step policy, refuses beyond -120 mV, needs `--yes`). Whether the BIOS allows undervolting on this laptop could not be checked from Windows; `uv-check` tells you on Linux. Untested.
